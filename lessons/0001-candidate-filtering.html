0001 — The Heuristic Stage Before the Judge

Stage 3 Candidate Filtering — the gate between discovery.py:40 (finds everything shared) and judge.py (asks LLM "real coupling?"). 5-minute lesson, one tangible win: you can predict what gets dropped before an LLM is ever called.

1. Parse→2. Discovery→3. Filtering ★→4. LLM Judge→5. Model→6. Graph

Why this stage exists

Discovery is greedy: same PORT key with 8000 vs 9000 still becomes a Candidate with value=None and evidence "different values" (discovery.py:82). If you sent that to an LLM you'd pay for every generic coincidence. Filtering applies deterministic, cheap heuristics first — AGENTS.md:65 "Filtering Before LLM" — and builds evidence for what remains.

Core principle: Shared Names ≠ Dependencies (AGENTS.md:52, DECISIONS.md:D-005). Identical PORT, DEBUG, LOG_LEVEL are usually coincidence, not coupling.

What it does (exact rules)

Input: List[Candidate] with resource (key/name) + value (shared value or None). Output: kept list, each with evidence + " | filter: kept — <reason>".

// src/blindspot/filtering.py:41  _decide(candidate)
if resource_type == "named_volume"               → KEEP   // strong signal
if env_var and value is None and "different values" in evidence → DROP
if env_var and resource in GENERIC_ENV_KEYS     → DROP   // PORT, DEBUG, LOG_LEVEL, APP_ENV, DATA_PATH, SHARED_*
if env_var and value is not None and specific   → KEEP + enrich
else if both None                               → KEEP weak // needs LLM

Full table: Reference cheat sheet. List at filtering.py:12.

See it on your fixtures

shared_env:  3 discovered (DB_HOST, DB_NAME, SHARED_EXTRA) → filter → 2 kept (DB_HOST, DB_NAME)
shared_volume: 2 (shared-data volume + DATA_PATH env)      → 1 kept (shared-data)
near_miss:  3 (PORT different-values + APP_ENV + SHARED_NOISE) → 0 kept  ← the whole point

Run it yourself:

PYTHONPATH=src python -c "
from blindspot.parser import parse_compose_file
from blindspot.discovery import discover_candidates
from blindspot.filtering import filter_candidates, filter_with_reasons
p=parse_compose_file('fixtures/near_miss/docker-compose.yml')
cands=discover_candidates(p)
for c,keep,reason in filter_with_reasons(cands):
    print(keep, c.resource, c.value, '—', reason)
"
