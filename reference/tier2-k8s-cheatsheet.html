Reference: Tier 2 Kubernetes Sources

Compressed map of what BlindSpot scans in K8s manifests. Print this. Full lesson: Lesson 0004.

Workload Kinds → Normalized Workload

Deployment / StatefulSet / DaemonSet / Job / CronJob / Pod → Workload{ name, namespace, containers[], env[], envFrom[], volumes[] }
Only Pod-template carriers. Ignore ConfigMap / Secret / PVC as workloads — they are resources, not services. Keep metadata.namespace (default: default) + source file for provenance.

Three Candidate Sources

SourceFields to scanExample
Shared ConfigMapenvFrom[].configMapRef.name, env[].valueFrom.configMapKeyRef.{name,key}, volumes[].configMap.name, volumes[].projected.sources[].configMap.namegame-demo in two Deployments
Shared SecretenvFrom[].secretRef.name, env[].valueFrom.secretKeyRef.{name,key}, volumes[].secret.secretName, projected.sources[].secret.namedb-creds in api + worker
Shared volumevolumes[].persistentVolumeClaim.claimName, same configMap/secret volume name, hostPath.path (same path only)claimName: shared-data

Signal vs Noise (Stage 3 preview)

KEEP (needs judgment):
  app ConfigMap  game-demo, app-settings
  credential Secret  db-creds, api-tokens
  shared PVC  claimName: shared-data

DROP (obvious noise, 0 LLM calls):
  projected service-account token  kube-api-access-*
  generic env keys  PORT, DEBUG, LOG_LEVEL (same as Tier 1)
  different keys, same ConfigMap name only in unrelated ns (namespace differs → identity differs)

Resource Identity (dedup key)

configmap:<namespace>/<name>   e.g. configmap:default/game-demo
secret:<namespace>/<name>      e.g. secret:prod/db-creds
pvc:<namespace>/<claimName>    e.g. pvc:default/shared-data

Namespace is part of identity — same name in different namespaces = different resources. Type is part of identity — configmap:game-demo ≠ secret:game-demo (same rule as Tier 1 env_var:REDIS ≠ named_volume:REDIS).

Resolution Check (before LLM)

FOUND    ConfigMap/Secret object exists in parsed manifests → attach data keys
MISSING  referenced name has no object → mark unresolved, keep conservatively
PARTIAL  workload uses only 1 key of a 20-key ConfigMap → record keys_used (bounded)

Boundary

No separate downstream. K8s candidates enter the same Filtering → Judge (1/group, cached) → CouplingModel → Graph (Service ↔ Resource) → Report pipeline (AGENTS.md:385, DECISIONS.md:D-012).
